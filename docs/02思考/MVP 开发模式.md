做东西要先做出 MVP ，**Minimum Viable Product**，中文“最小可行产品”。也就是把关键的核心链路做出来，并且可以跑通。可以简陋，比如 UI 很丑，但是必须完整。做出来之后，根据需求，评估 MVP ，进而开始迭代和优化。

这才是做项目的一个比较合理的模式，而不是一上来就要做到最好。

这也是我在寻找的，做 voicecast 的流程，claude 无意中带出来的，只是不知道这个做法是什么。今天在学[[02思考/基础 RAG|基础 RAG]] 的时候，在那个视频的最后，up 主讲到了这种开发模式，当时给我留下了很深的印象。

这种开发模式我认为有两个好处。一，能对自己做的东西，有一个感觉。假设一直在开发，产品就只能存在于理想中，自己是用不到的。随着时间的流逝，一直用不到产品，热情就会降低。但是如果做出来 MVP ，自己就可以使用它，就，有那种感觉。二，能有反馈。做出来上线之后，或者内测，能得到用户的反馈，有利于解决真正的问题。而不是自己埋头脑补问题。要知道，产品要解决的是用户的问题，只有给用户使用，才能知道用户真正想要的是什么。
