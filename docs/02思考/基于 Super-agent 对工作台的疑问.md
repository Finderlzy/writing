这些工作台，如果不使用反代，是如何做到在一个工作台调用多个agent的？

我一直以来的想法都是，一个工具的开发，必然是为了解决一定的问题，这次也不例外。我想把我自己从 agent 的工作中抽离出去。我发现我在agent工作中的作用很小：在项目开始之前我会明确我的需求，将其拆分为几个里程碑；每个里程碑开始之前，我还会和agent确定细致的需求，达成共识之后agent制定计划。然后我就变成搬运提示词的机器了，但是我还不得不把时间放在这上面，详情你可以看我的matt套件。所以我想把我从开始执行任务这个环节抽离出去，我打算参考super-agent的架构。

我的第一个想法是做一个skill——dispatch。成功是成功了，但是任务执行的质量非常差。第一个任务跑了一个小时，干活的那个重复了700次工具调用；第二个任务也是跑了20min，还是没好。于是我就发现了一些问题：一是模型的能力很重要，但是为了节约成本，我不希望所有任务都用强力的模型做；二是使用这个skill的对话，我们暂且定义为“伪Router层”，还是有能力执行命令，也就是他会干活；三是没有看门狗；四是无法做到理想的事件监听，不过这个我不着急
