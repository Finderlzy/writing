RAG 是用来解决大模型无法较好地回答**私域问题**这个现象的。什么是“私域问题”？简单来讲就是关于某个企业内部性的知识的问题，如：A 企业的打卡标准、奖金标准。为什么大模型无法较好地回答？因为没有知识。大模型的回答一是基于**训练的数据集**，二是基于**联网搜索**。而有关私域问题的文档大模型是搜集不到的，因此没有相关的准确知识，也就无法很好地回答了。

RAG，全名是 **Retrieval-Augmented Generation** ，中文名“检索增强生成”。可以理解为：通过**检索**找到问题所需要的文档，提供给大模型，从而**增强**大模型的**生成**效果。简单来讲，RAG 就是把大模型没有的那些知识，提供给大模型。

RAG 的简易流程
![[09附件/Pasted image 20261107121351.png]]

红色：准备文档（离线处理）—— 先把原始资料分块，然后把 **文本块（chunk）** 转化为向量，目前主流的 Embedding 方法是“词嵌入”：对于每一个词，都使用很多维度去描述。最后存储进向量数据库，向量数据库存储的东西：

| id   | 向量                 | 元数据                |
| ---- | ------------------ | ------------------ |
| 0001 | （0.12, -0.03, ...） | 文本块内容、来源、时间、...... |

为什么要转化为向量？因为计算机只能处理数字，无法处理文本。

黄色：数据的加工过程

蓝色：线上提问——先把问题转化为向量，然后在数据库中找到相似度比较近的几个（参考）向量，把（参考）向量对应的元数据提供给大模型，也就是有了参考文档。
