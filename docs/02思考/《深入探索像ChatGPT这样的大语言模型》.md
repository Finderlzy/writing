## 预训练
---
把整个互联网当中的文本，当作模型的训练知识，输入给模型。

当然，并不是直接把那些文本输入给模型，而是会做一个处理——tokenization。把文本变成一个一个的 token 。怎么变？最简单的想法就是对文本进行 UTF-8 处理，也就是变成一大堆的 0 和 1 。但是这样子太长了，于是学者们想出了别的方法，给每一个词赋予一个 ID 。但是这样子还是需要很多的 ID ，也就是一维序列太长了。学者们再次优化，把经常连在一起出现的短语，也赋予一个 ID 。这些词、短语在模型眼里就是一个一个的 ID ，也就是 **token** 。

从训练集中，随意挑选一些文本（token），让模型预测下一个 token 会是什么。模型会把这些 token 和一些参数一起输入到一个复杂的数学表达式中，得出众多 token 可能会是下一个的概率，**看正确答案那个 token 拿到了多少概率，然后调整参数，让它的概率变高一点**。因为是很难达到 100% 的概率，也就是说，几乎每轮训练都有进步空间。这就是训练的过程。


## 推理
---
最后会得到一个 Base 模型，只是这个时候，模型更像是互联网的预测机器。把用户的输入转化为 token ，然后把这些 token 和训练好确定下来的参数一起放入那个数学公式中，得到众多 token 可能出现在下一个词的概率，然后**随机采样**（不是直接拿概率最高的那个）。这个过程就叫做“推理”。


## 监督与微调训练
---
在这一阶段，我们会自己写训练集，在训练集中，写入我们用户的提问，以及**用户所希望的模型的回答**，然后让模型再次训练，调整参数（现在有的监督与微调训练不直接调整 Base 模型的参数，而是新增一些参数，如 LoRa）。

这一步训练完，得到 SFT 模型，这个时候，模型像是一个模仿 labler（制作出训练集的专家） 的机器。


## 强化学习
---
karpathy 指出，模型在解题（比如做数学题）的时候，如果是一步一步作答，效果会比直接写出答案好。因为一步一步作答，每一次生成的中间步骤，都会被加入到下一个 token 的预测之中。而我们并不知道，哪样子的中间作答，能够有利于得到正确答案。于是就让模型生成很多个回答，然后得到一些成功得到正确答案的回答。基于这些回答，调整参数。

voicecast 是否可以借鉴强化学习的思想，来让模型越用效果越好呢？现在每次都会生成三段音频，然后让用户挑选出最好的那一段。这里就是在认为选择比较好的那一段，那该如何让下一次生成往这个方向靠近呢？直接修改 GPT 和 SoVITS 的参数，让下一次合成的中间推理过程，往这次合成的中间推理过程靠近？

## 幻觉
---
LLM 的本质就是预测下一个 token ，所以有的时候，在我们看来它会自己“编造”一些不存在的东西，或者回答错误，这就是所谓的“幻觉”。为什么它会编造？因为微调的时候，我们的训练集都是很自信的回答，而它就是一个模仿者，所以就会产生“幻觉”。解决方法是在训练集中，**拿一批有标准答案的问题反复问模型，找出它总是答错的那些，也就是它真的不知道的，然后只给这些问题配上"我不知道"。这样模型学到的是"当我内部不确定的时候，就说不知道"**。而不是随便就给模型的回答是“我不知道”。


## 一些感觉
---
在模型眼里，一切都是 token ，根本不存在什么文本。模型的回答，就是根据我的输入的 token ，一个 token 一个 token 地推断下一个 token 是什么。多想想 karpathy 给出的那个带有 transformer 架构的图。


## 一些疑问
---
为什么模型的性能不一样？

第一个原因，参数量不同。

那在同等规模的参数量上，模型的性能依然有区别。让我们先回到模型回答的本质：预测下一个 token 的概率。如何预测？数学公式。数学公式的输入是用户的提问和参数。用户的提问是相同，所以这个问题其实就是在问：**不同的模型为什么最终的参数不同**？

回顾前文，有三个可以影响参数的地方——预训练、监督和微调训练、强化学习。而这些阶段中，大家用到的思路，我觉得应该是大差不差的。不过我也不确定，这是我的下意识假设。基于这个假设，对于上面的问题的回答是：**训练集**不一样。虽然预训练训练集可能差不多，但是每家公司或多或少会有所取舍，因此效果不一样。另外，监督和微调训练的训练集可能是比较重要的影响因素。然后，强化学习会放大这种影响。最终呈现出来的，就是不同的模型性能不一样。

那如果训练集也完全一样呢？最终模型的性能是否就会完全一样？如果是基于上面的**训练思路大差不差**的假设，我认为应该是一样的。但是实际情况中，我认为不同公司训练的时候，调整参数的算法应该是不一样的。
