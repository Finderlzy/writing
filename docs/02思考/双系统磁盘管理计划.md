## 目标

每个盘只有一个明确的用途，新东西该放哪里不用想。核心原则是**代码共享，环境分开**：源码是纯文本，两个系统都能用；虚拟环境、编译产物里是各系统自己的二进制文件，不能混用。

|盘|用途|谁在用|
|---|---|---|
|C|Windows 系统 + 只能装 C 盘的软件|Windows|
|D|软件、游戏、开发工具、Windows 的环境和缓存|Windows|
|E|**共享**：代码、文档、媒体、模型、数据集、下载|两边共用|
|Ubuntu 自己的分区（ext4）|Ubuntu 系统、Ubuntu 的环境和缓存|Ubuntu|

## 三条规则

1. **E 盘放共享的代码和数据，不放环境。** conda 环境、`.venv`、编译产物各放各系统的盘里，各配一套
2. **按下面的命名规则起名。** Linux 终端里打路径会方便很多
3. **媒体文件按类型分，其余按用途分。** 新东西先进 `E:\Downloads`，定期分拣到对应文件夹，不留「好东西」这类杂物文件夹

## 命名规则

1. **一级文件夹用英文，每个词首字母大写，不加空格**，如 `Books`、`Models`、`Wallpaper`、`Backups`。缩写保持全大写，如 `USTB`
2. **系统默认文件夹用标准英文名**：`Desktop`、`Downloads`、`Documents`、`Pictures`、`Videos`、`Music`，和 Windows、Ubuntu 英文版的默认名一致
3. **二级及以下可以用中文**（课程名、书名），但不加空格，需要分隔时用 `-`。已有的文件不强制改名
4. **日期放在开头，写成 `YYYY-MM-DD`**
5. **代码仓库用小写加连字符**，如 `writing`、`local-asr`
6. **共享盘的禁忌**：不用 `: * ? " < > |`，名字末尾不留空格或点，不建只差大小写的同名文件

`WorkSpace` 按规则应写成 `Workspace`，但很多配置记着这个路径，保持不改。

## 目录结构

**E 盘（共享）**

```
E:\
├─ Desktop\  Downloads\  Documents\  Pictures\  Videos\  Music\   ← 系统默认文件夹
├─ WorkSpace\   代码仓库，两边共用同一份（不放环境）
├─ USTB\        学校资料和作业，按学期/课程分
├─ Books\
├─ Models\      模型权重（llama.cpp 的模型、HuggingFace 缓存）
├─ Datasets\    数据集、训练素材
├─ Wallpaper\
├─ Backups\
└─ 密码.kdbx    KeePass 密码库
```

**D 盘（Windows 专用）**

```
D:\
├─ Program Files\         ← 图形界面软件
├─ Program Files (x86)\
├─ Games\                 ← 游戏
├─ WeGameApps\
├─ Xilinx\
├─ Dev\
│  ├─ Tools\    命令行工具：Maven、mingw64、Go、llama.cpp、miniconda3…
│  ├─ Envs\     Windows 的 conda 环境
│  └─ Caches\   包管理器缓存：conda、pnpm、npm、pip、uv、Maven
├─ DevTools\              ← 用安装程序装的 Git、Java、MySQL、Python
├─ Drivers\               ← 驱动备份，重装系统时有用
└─ 系统文件夹
```

## 放置规则

|新东西|放哪里|
|---|---|
|图形界面软件|`D:\Program Files`|
|游戏|`D:\Games`|
|命令行开发工具|`D:\Dev\Tools`，并加进 `Path`|
|代码|`E:\WorkSpace`，两边共用|
|Windows 的环境|`D:\Dev\Envs`（conda）|
|Ubuntu 的环境|Ubuntu 自己的分区（conda）|
|模型、数据集|`E:\Models`、`E:\Datasets`|
|下载的东西|`E:\Downloads`，定期分拣|

## 注意事项

### 挪动软件和工具

- **用安装程序装的软件不要剪切。** 注册表、快捷方式、环境变量里都记着它的路径，挪了就打不开。D 盘的 `Program Files`、`DevTools`、`WeGameApps`、`Xilinx` 以及系统文件夹都保持原地；真想换位置只能卸载重装
- **解压即用的工具可以挪，但一次只挪一个。** 挪完改 `Path` 和 `MAVEN_HOME` 这类变量（系统变量要管理员权限），新开终端测试命令能用，再挪下一个。工具自己的配置文件里也可能写着绝对路径，比如 Maven 的 `conf\settings.xml`
- **缓存位置要用工具自己的方式改**，不能只搬文件夹：npm、pip、uv 用环境变量，pnpm 用 `pnpm config set store-dir`，Maven 改 `settings.xml`
- **记着自己路径、又不方便重装的东西**（比如 conda 本体、脚本写死路径的 `.venv`），可以复制到新位置后，在原位置建目录联接：`New-Item -ItemType Junction -Path 旧路径 -Target 新路径`。确认能用再删备份

### 环境

- **建环境用 conda 的名字**：`conda create -n 项目名 python=3.12`，会建到 `D:\Dev\Envs\项目名`。Ubuntu 那边用同一个名字
- **Node 项目**的 `node_modules` 必须在项目里，换系统后按锁文件重装一次（`npm ci` 或 `pnpm install`）
- **要编译的项目**，编译产物按系统分开，如 `build-win`、`build-linux`，都加进 `.gitignore`

### 共享代码

- **Git 换行**：Windows 设 `core.autocrlf = input`，检出时保持 LF，Ubuntu 打开不会整个文件显示已修改
- **文件权限**：NTFS 挂到 Linux 后所有文件都显示可执行。仓库里设 `git config core.filemode false`，这个设置在 `.git/config` 里，两边共用
- **换系统后第一次 `git status` 会慢**：Git 要重新扫描文件，正常现象
- **文件名大小写**：Linux 区分大小写，Windows 不区分。共享目录里不要建只有大小写不同的文件

### 系统

- **切换系统要彻底关机**，快速启动和休眠保持关闭，否则 Ubuntu 挂载 NTFS 盘时可能只读，强行写入还可能损坏数据
- **自己设过存储路径的软件**（QQ、微信等）不会跟着系统文件夹走，要在它们的设置里单独改
- **新内容的保存位置**（设置 → 系统 → 存储 → 高级存储设置）保持为 D 盘，否则新应用、地图会被装到 E 盘
- **敏感文件**（token、恢复码）存进 KeePass，不要明文放在共享盘上。`密码.kdbx` 在云盘另存一份，Ubuntu 用 KeePassXC 打开同一个文件

### Ubuntu

- **E 盘写进 `/etc/fstab` 开机挂载**到 `/run/media/finderzly/E`（ntfs3，`uid=1000,gid=1000`，加 `nofail`），文件归自己，不用设 `safe.directory`。不能等登录后再自动挂载：用户文件夹和自启程序都在 E 盘上，登录时盘还没挂上，链接就会失效
- **家目录不留 `~/Workspace`**，直接在 `/run/media/finderzly/E/WorkSpace` 里干活。配置、文档里的路径都写这个完整路径，大小写也要一致（ntfs3 区分大小写）；Obsidian 仓库、Git worktree、Claude 会话也从这里打开
- **Node 项目在 Ubuntu 上第一次用前按锁文件重装依赖**：有 `package-lock.json` 的跑 `npm ci`，有 `pnpm-lock.yaml` 的跑 `pnpm install`。`node_modules` 没有跟着迁过来
- **用户文件夹用英文名**：`~/Desktop`、`~/Documents`、`~/Downloads`、`~/Pictures`、`~/Videos`、`~/Music`、`~/Templates`、`~/Public`。`~/.config/user-dirs.locale` 设为 `en_US`，系统更新后不会再提示改回中文
- **`~/Documents`、`~/Downloads`、`~/Pictures`、`~/Videos`、`~/Music` 是指向 E 盘同名文件夹的链接**，两个系统看到的是同一份文件。`~/Desktop`、`~/Templates`、`~/Public` 留在 Ubuntu 分区。E 盘这几个文件夹原来有 Windows 的只读属性，Linux 写不进去，已经清掉；代价是资源管理器里显示英文名，不再显示「文档」「下载」
- **微信两边共用 `E:\Documents\xwechat_files`**。Ubuntu 原来那份存在 `E:\Backups\2026-11-03-xwechat_files-ubuntu`
- **不用 uv 和 `.venv`**，环境一律 `conda create -n 项目名`，建在 `~/miniconda3/envs`。命令写成 `conda run -n 项目名 python …`。原来各 venv 的包列表存在 `E:\Backups\2026-11-03-ubuntu-venvs`
- **定时任务写的备份留在家目录**，如 `~/Backups/dafeiyu`（每天拉取、保留 30 份），不依赖 E 盘挂载
- **根分区只有 85G**，模型、数据集直接放 E 盘；`~/Downloads` 本身就在 E 盘，下载不占根分区
- **Ubuntu 分区不够用时**，再从 D 盘末尾[[04博客/在win11中额外安装ubuntu系统|压缩出空间]]。D 盘根目录的 `pagefile.sys` 最可能卡住压缩，被卡住时先在「系统属性 → 高级 → 性能设置 → 虚拟内存」里临时关掉 D 盘的分页文件，重启后再压缩，压缩完再打开
