## 目标

每个盘只有一个明确的用途，新东西该放哪里不用想。核心原则是**代码共享，环境分开**：源码是纯文本，两个系统都能用；虚拟环境、编译产物里是各系统自己的二进制文件，不能混用。

|盘|用途|谁在用|
|---|---|---|
|C|Windows 系统 + 只能装 C 盘的软件|Windows|
|D|软件、游戏、开发工具、Windows 的环境和缓存|Windows|
|E|**共享**：代码、文档、媒体、模型、数据集、下载|两边共用|
|Ubuntu 自己的分区（ext4）|Ubuntu 系统、Ubuntu 的环境和缓存|Ubuntu|

## 三条规则

1. **E 盘放共享的代码和数据，不放环境。** conda 环境、`.venv`、编译产物各放各系统的盘里，各配一套
2. **按下面的命名规则起名。** Linux 终端里打路径会方便很多
3. **媒体文件按类型分，其余按用途分。** 新东西先进 `E:\Downloads`，定期分拣到对应文件夹，不留「好东西」这类杂物文件夹

## 命名规则

1. **一级文件夹用英文，每个词首字母大写，不加空格**，如 `Books`、`Models`、`Wallpaper`、`Backups`。缩写保持全大写，如 `USTB`
2. **系统默认文件夹用标准英文名**：`Desktop`、`Downloads`、`Documents`、`Pictures`、`Videos`、`Music`，和 Windows、Ubuntu 英文版的默认名一致
3. **二级及以下可以用中文**（课程名、书名），但不加空格，需要分隔时用 `-`。已有的文件不强制改名
4. **日期放在开头，写成 `YYYY-MM-DD`**
5. **代码仓库用小写加连字符**，如 `writing`、`local-asr`
6. **共享盘的禁忌**：不用 `: * ? " < > |`，名字末尾不留空格或点，不建只差大小写的同名文件

`WorkSpace` 按规则应写成 `Workspace`，但很多配置记着这个路径，保持不改。

## 目标结构

**E 盘（共享）**

```
E:\
├─ Desktop\  Downloads\  Documents\  Pictures\  Videos\  Music\   ← 系统默认文件夹
├─ WorkSpace\   代码仓库，两边共用同一份（不放环境）
├─ USTB\        学校资料和作业，按学期/课程分
├─ Books\       原「各种书」
├─ Models\      模型权重（llama.cpp 的模型、HuggingFace 缓存）
├─ Datasets\    数据集、训练素材
├─ Wallpaper\
├─ Backups\
└─ 密码.kdbx    KeePass 密码库
```

**D 盘（Windows 专用）**

```
D:\
├─ Program Files\         ← 图形界面软件（保持现状，以后继续装这里）
├─ Program Files (x86)\
├─ Games\                 ← 以后新装的游戏
├─ WeGameApps\            ← 已有，不动
├─ Xilinx\                ← 已有，不动
├─ Dev\
│  ├─ Tools\    命令行工具：Maven、mingw64、Go、llama.cpp、miniconda3…（原 DevTools）
│  ├─ Envs\     Windows 的 conda 环境
│  └─ Caches\   包管理器缓存：conda、pnpm、npm、pip、uv、Maven（原 DevCaches + .pnpm-store）
├─ DevTools\              ← 只剩用安装程序装的 Git、Java、MySQL、Python，不动
├─ Drivers\               ← 原 ASUS-Driver-Backup，重装系统时有用
└─ 系统文件夹（不动）
```

**D 盘里不能碰的文件夹**

已装的软件在注册表、快捷方式、环境变量里记着自己的路径，剪切到别处就打不开。D 盘的原则是：**已装的软件不动，新装的按新结构放，只整理能随便挪的东西。**

|文件夹|是什么|处理|
|---|---|---|
|`$RECYCLE.BIN`、`System Volume Information`、`Config.Msi`、`DumpStack.log.tmp`、`pagefile.sys`|Windows 系统文件|不动|
|`WindowsApps`、`WpSystem`|微软商店应用装在 D 盘时生成|不动|
|`ProgramData`、`Users`|某些软件建的|不动|
|`DeliveryOptimization`|Windows 更新缓存|不动|
|`ASUS`|华硕自带软件|不动|
|`Program Files`、`Program Files (x86)`、`WeGameApps`、`Xilinx`|软件和游戏|不动|
|`DevTools` 里的 Git、Java、MySQL、Python313|用安装程序装的，路径记在注册表里|不动|
|`DevTools` 里的其余工具、`DevCaches`、`.pnpm-store`|解压即用的工具和缓存|第 3、4 步迁移|
|`BaiduNetdiskDownload`、`QuarkDownload`、`Ubuntu-Videos`|下载和视频|第 2 步搬到 E 盘|
|`MineradioCache`、`Temp`|缓存|确认没用后清理|

## 操作步骤

### 第 0 步：准备（Windows）

1. 确认 `E:\WorkSpace` 里每个仓库都已经 push 到 GitHub
2. 把 `密码.kdbx` 另存一份到云盘

### 第 1 步：整理 E 盘（Windows）

1. 按上面的结构建好文件夹
2. 搬走不属于共享盘的东西：
   - USTB 里的软件和开发工具 → `D:\Dev\Tools`，USTB 里只留资料和作业
   - llama.cpp 这类程序本体 → `D:\Dev\Tools`，它们的模型文件放 `E:\Models`
3. 「好东西」里的内容按类别分进去，然后删掉这个文件夹
4. 「各种书」改名为 `Books`
5. `token.txt`、恢复码这类敏感文件存进 KeePass 后删掉原文件，不要明文放在共享盘上

### 第 2 步：下载类文件夹搬到 E 盘（Windows）

1. `BaiduNetdiskDownload`、`QuarkDownload` 里的文件分拣到 E 盘对应文件夹
2. 在百度网盘、夸克的设置里把下载位置改成 `E:\Downloads`
3. `Ubuntu-Videos` 搬到 `E:\Videos`

### 第 3 步：命令行工具迁到 `D:\Dev\Tools`（Windows）

这类工具大多解压即用，可以挪，但挪完要改环境变量 `Path`（Windows 靠它找到 `java` 这类命令）。**一次只挪一个：**

1. 把工具文件夹挪进 `D:\Dev\Tools`
2. 开始菜单搜「环境变量」→ 编辑 `Path`，把旧路径改成新路径。`MAVEN_HOME` 这类变量也一起改；系统变量要管理员权限
3. 新开一个终端，测试命令能用（如 `mvn -v`）
4. 能用再挪下一个

**用安装程序装的（Git、Java、Python、MySQL）不要挪**，路径记在注册表、开始菜单和虚拟环境里，挪了会坏。真想换位置只能卸载重装。

工具自己的配置文件里也可能写着绝对路径，挪完要检查。比如 Maven 的 `conf\settings.xml` 里的 `localRepository`。

### 第 4 步：缓存迁到 `D:\Dev\Caches`（Windows）

缓存位置要用工具自己的方式改，不能只搬文件夹。都在 D 盘内部时，可以直接把旧缓存整体挪过去，不用重新下载：

|工具|改什么|
|---|---|
|npm|用户变量 `NPM_CONFIG_CACHE` + `.npmrc` 里的 `cache=`|
|pip|用户变量 `PIP_CACHE_DIR`|
|uv|用户变量 `UV_CACHE_DIR`|
|pnpm|`pnpm config set store-dir D:\Dev\Caches\pnpm-store`，`cache-dir` 同理|
|Maven|`settings.xml` 里的 `localRepository`|

改完重开终端，用 `npm config get cache`、`pip cache dir`、`uv cache dir`、`pnpm store path` 确认。用过 pnpm 的项目下次安装时可能提示 store 位置变了，同意重装即可。

### 第 5 步：环境统一用 conda（Windows）

conda 的环境本来就建在它自己的目录里，不进项目文件夹，正好符合「E 盘不放环境」。

1. **conda 本体放 `D:\Dev\Tools\miniconda3`。** 已经装在 C 盘的，不能直接剪切（里面到处记着安装路径），做法是：
   1. 用 `robocopy` 把整个文件夹复制到 `D:\Dev\Tools\miniconda3`，核对文件数和大小一致
   2. 原文件夹改名作备份，在原位置建目录联接指向 D 盘：`New-Item -ItemType Junction -Path C:\Users\ASUS\miniconda3 -Target D:\Dev\Tools\miniconda3`
   3. 新开终端测试 `conda activate`，确认环境能用后再删备份
2. **新环境和包缓存指向 D 盘：**

   ```
   conda config --add envs_dirs D:\Dev\Envs
   conda config --add pkgs_dirs D:\Dev\Caches\conda-pkgs
   ```

3. **建环境用名字**：`conda create -n 项目名 python=3.12`，环境会建在 `D:\Dev\Envs\项目名`。Ubuntu 那边用同一个名字，两边用法一样
4. **项目里已有的 `.venv`**：能用 conda 重建就重建，跑通后删掉旧的；脚本里写死了 `.venv` 路径、不方便改的，可以把 `.venv` 挪到 D 盘，再在原位置建目录联接

几种环境挪不出项目的情况：

- **Node 项目**：`node_modules` 必须在项目里。换系统后跑一次 `pnpm install` 重装
- **要编译的项目**：编译产物按系统分开，如 `build-win`、`build-linux`，都加进 `.gitignore`
- **只在一个系统用的项目**（如 Vivado 工程）：留在 E 盘也没坏处，就当只有一边在用

### 第 6 步：Windows 系统设置

1. **默认文件夹指向 E 盘**：资源管理器里右键「下载」「图片」「视频」「音乐」「文档」「桌面」→ 属性 → **位置** → 移动，选 E 盘对应的英文文件夹
2. **自己设过存储路径的软件**（QQ、微信等）要在它们的设置里单独改，不会跟着系统文件夹走
3. **HuggingFace 缓存**：开始菜单搜「环境变量」→ 用户变量 → 新建 `HF_HOME`，值为 `E:\Models\huggingface`
4. **新内容的保存位置**：设置 → 系统 → 存储 → 高级存储设置 → 新内容的保存位置，新应用、地图都改成 D 盘
5. **确认快速启动已关闭**，否则 Ubuntu 挂载 NTFS 盘时可能只读，强行写入还可能损坏数据

### 第 7 步：Ubuntu 配置（Ubuntu）

1. 把 E 盘挂载到 `/mnt/shared`，设置开机自动挂载
2. 把 Ubuntu 里的共享数据（文档、图片、代码等）搬到 E 盘，腾出 Ubuntu 分区的空间
3. 给共享代码建软链接：`ln -s /mnt/shared/WorkSpace ~/WorkSpace`
4. 安装 conda，环境留在 Ubuntu 自己的分区，和 Windows 用同样的环境名
5. 让 Ubuntu 的默认文件夹（文档、音乐、图片、视频、下载、桌面）指向 E 盘对应文件夹
6. 安装 **KeePassXC**，打开 E 盘上的同一个 `密码.kdbx`
7. 浏览器下载位置设为 `E:\Downloads` 对应的挂载路径

**如果以后 Ubuntu 分区不够用**，再从 D 盘末尾[[04博客/在win11中额外安装ubuntu系统|压缩出空间]]：磁盘管理 → 右键 D 盘 → 压缩卷。D 盘根目录的 `pagefile.sys`（虚拟内存文件）最可能卡住压缩，被卡住时先在「系统属性 → 高级 → 性能设置 → 虚拟内存」里临时关掉 D 盘的分页文件，重启后再压缩，压缩完再打开。

## 共享代码的注意事项

- **Git 换行**：Windows 设 `core.autocrlf = input`，检出时保持 LF，Ubuntu 打开不会整个文件显示已修改
- **文件权限**：NTFS 挂到 Linux 后所有文件都显示可执行。仓库里设 `git config core.filemode false`，这个设置在 `.git/config` 里，两边共用
- **换系统后第一次 `git status` 会慢**：Git 要重新扫描文件，正常现象
- **文件名大小写**：Linux 区分大小写，Windows 不区分。共享目录里不要建只有大小写不同的文件
- **切换系统要彻底关机**，不要休眠后切换

## 以后的放置规则

|新东西|放哪里|
|---|---|
|图形界面软件|`D:\Program Files`|
|游戏|`D:\Games`|
|命令行开发工具|`D:\Dev\Tools`，并加进 `Path`|
|代码|`E:\WorkSpace`，两边共用|
|Windows 的环境|`D:\Dev\Envs`（conda）|
|Ubuntu 的环境|Ubuntu 自己的分区（conda）|
|模型、数据集|`E:\Models`、`E:\Datasets`|
|下载的东西|`E:\Downloads`，定期分拣|
