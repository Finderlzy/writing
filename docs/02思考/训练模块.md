从上往下思考

Spring 帮忙建好一个 TrainingService 的实例，传进来给 TrainingController 。TrainingController 监听 /train 路径，有请求发过来的时候，必须要有两个参数：expName 实验名字和 sliceDir 切分后的音频放的文件夹。如果没有参数，就返回一个IllegalArgumentException 。

调用 Service 的 submit() 方法，传入 expName 和 sliceDir 作为参数。

Spring 帮忙创建好 TrainingPipeline 、GsvLauncher 的实例，传入 Service 。然后把实验的工作目录写好 workDir 。

Service.submit() 方法：先判断 expName 和 sliceDir 有没有问题，就是实验名字最好是字母数字加下划线。然后没问题之后，创建一个实验 id ，传入 TrainingJob ，新建一个 Job 实例，用来追踪本次请求的状态。

下面列举出了 Job 记录的一些状态：
```java
// 枚举：订单只可能处于这四种状态之一
public enum Status { QUEUED, RUNNING, SUCCEEDED, FAILED }
public static final int TOTAL_STEPS = 7; // 变量（常量）：一共 7 个子进程步骤

private final String id; // 变量（字段）：取餐号
private final String expName; // 变量（字段）：实验名，比如 iroha_t2
private final Path sliceDir; // 变量（字段）：切好的 wav 所在文件夹
private final Instant createdAt; // 变量（字段）：下单时间

// 下面这些会被后台线程修改、被请求线程读取，所以都加 volatile
private volatile Status status = Status.QUEUED;
private volatile int step = 0; // 当前第几步（1～7），0 表示还没开始
private volatile String stepName = "排队中";
private volatile double stepProgress = 0; // 当前这一步完成了多少（0～1）
private volatile String sovitsWeight; // 产出的 SoVITS 权重路径
private volatile String gptWeight; // 产出的 GPT 权重路径
private volatile String error; // 失败时的原因

public TrainingJob(String id, String expName, Path sliceDir) {

	this.id = id;
	this.expName = expName;
	this.sliceDir = sliceDir;
	this.createdAt = Instant.now();
}
```

创建好这个 Job 之后，把它丢到 jobs（一个 Map 实例，里面装着所有的 Job）里面。接着使用**后台线程**调用 Service.runjob() 方法。

Service.runjob()方法：先设置状态为 RUNNING ，关闭 GSV ，调用 Pipeline 的 run() 方法。

Pipeline.run()方法。先把目录创建好，然后依次执行训练的步骤。
```
public void run(TrainingJob job) throws Exception {

	Path base = workDir.resolve(job.getExpName()); // 变量 base：我们自己的实验目录（清单、配置、日志）
	
	Path optDir = gsvDir.resolve("logs").resolve(job.getExpName()); // 变量 optDir：GPT-SoVITS 的实验目录（预处理产物）
	
	Files.createDirectories(base);
	Files.createDirectories(optDir);
	
	Path trainList = asr(job, base); // 第 1 步
	getText(job, base, trainList, optDir); // 第 2 步
	getHubert(job, base, trainList, optDir); // 第 3 步
	getSv(job, base, trainList, optDir); // 第 4 步
	getSemantic(job, base, trainList, optDir); // 第 5 步
	log.info("[{}] 预处理完成", job.getExpName());
	
	trainSovits(job, base, optDir); // 第 6 步
	log.info("[{}] SoVITS 训练完成：{}", job.getExpName(), job.getSovitsWeight());
	
	trainGpt(job, base, optDir); // 第 7 步
	log.info("[{}] GPT 训练完成：{}", job.getExpName(), job.getGptWeight());
}
```

Pipeline.run() 跑完之后，回到 Service.runjob() ，把这个 job 的状态设置为 SUCCEEDED 并打印日志。然后重启 GSV 。

Service.runjob() 会抓异常，如果有异常被抛出，则会报错。但最后无论训练成功还是失败，都会重启 GSV 。

Service.submit() 跑完会返回一个 Job ，返回给 Controller 。
