编译，是把 C 程序，从我们能读懂的高级语言，翻译为**汇编语言**。汇编语言，是**机器码的助记符**。汇编，则是把汇编语言，翻译为机器码。机器码是 CPU 能读懂的东西，本质上是字节序列，也就是一堆“0”和“1” 。编译器是怎么一步一步把我们能看懂的高级语言翻译为机器码的呢？


## ISA ——指令集架构
---
这里不得不提到一个东西——ISA（ Instruction Set Architecture），指令集架构，可不是 isa 哦。我们在安装软件的时候，看到的所谓“x86-64”和“arm”就是 ISA 。ISA 规定了 CPU 怎么读取机器码：机器码的前几位是指令还是什么、某个机器码（比如“e8”）是什么含义、某个指令后面会跟多长，都是 ISA 决定的。

编译器会先确定本台电脑的 ISA ，根据本台电脑的实际 ISA ，先翻译为汇编语言，再翻译为机器码。


## 机器码
---
前面说过：机器码就是一大串的“0”和“1”。这里我们需要意识到，**CPU 是不会区分数据类型的**，它看见的就只是一大堆“0”和“1”，它是不知道这个是变量 a 那个是变量 b 的。那它是怎么做到对变量进行运算的呢？根据 ISA ，下面举一个例子。

假设有这么一段机器码：`b8 35 00 00 00` 。CPU 根据 ISA（假设是 x86-64），第一个字节 `b8` （往往是**操作码**，也就是指令）的意思是“把后面 4 个字节的数据放进寄存器”。然后 CPU 就会读取后面的四个字节 `35 00 00 00` （十六进制），也就是十进制的 53 ，放进寄存器里面。接着可能是下一段机器码，再对这个寄存器里面的这个数进行运算。这里再补充一点：**机器码的操作往往都是很简单的**。


## PC 根据机器码移动
---
现在，C 程序是怎么变成机器码，以及 CPU 是如何读懂机器码，都清楚了。到这里我就有一个问题。我们都知道，CPU 中有一个 PC ，专门用来指向下一个要运行的指令。那么，当 CPU 读取指令之后，PC 是怎么知道它接下来要移动到哪里的？

一般而言，还是根据 ISA 。ISA 会规定某一个指令的长度，当 CPU 取到这个指令之后，PC 就会根据 ISA 中规定的这个指令的长度，自动后移到下一个指令的末尾。比如上面的那个 `b8 35 00 00 00` ，当 CPU 读取到 `b8` 的时候，PC 就知道这个指令有 5 个字节的长度，就会后移了。

另外，有的指令直接就是移动 PC 。

程序就这么在 CPU 的**取指**、**译码**、**执行**、**访存**、**返回**的周期循环中运行下去。每一次取指，CPU 都会知道这个指令有多长，从而让 PC 指向下一条指令码，以及继续读取后面的指令。


## 恶意程序的简单原理
---
恶意程序，就是通过某种手段，**简单地推移了一下 CPU 的 PC**（专业一点叫做改变 CPU 的控制流），从而影响了所有的指令。这是如何做到的呢？还是用 `b8 35 00 00 00` 举例。正常来说，CPU 读到 `b8` 的时候会知道这个指令是“把后面 4 个字节的数据放进寄存器”，但是如果我稍微移动一下，让 PC 读到的指令码是 `83` ，而 `83` 的含义是告诉CPU：“后面紧跟着的 **ModR/M 字节** 中的 `reg` 字段，将决定最终执行的是加法、减法、比较等具体哪一种运算。” ......这个是我去搜索得到的，我看不懂。另外，**这个推移并不是只推移这一个指令**，要记得，PC 会根据 ISA 规定的指令的长度往后移动，指向下一个指令。也就是说，**所有的指令都会变乱**。
