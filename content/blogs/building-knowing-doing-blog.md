## 需求

- **轻量便捷**：在 Obsidian 里点一个按钮就能发布，不用手写 frontmatter 标记。
- **分享渠道**：有一个地方能方便地把文章给别人看。
- **多端同步**：手机上也能看自己的全部文章。
- **部分私密、部分发表**：私密的内容不能被别人从仓库源码里翻到。

## 整体架构

在这里说明一下有关这个博客的三个仓库。第一个仓库，**Obsidian 仓库**：我所有的文章都在这里写，后面提到的插件也装在这里。第二个仓库，**私密仓库**：GitHub 上的一个私密仓库，是 Obsidian 仓库关联的远端，用来同步我写的所有文章。第三个仓库，**博客仓库**：Quartz 所在的仓库 `finderlzy.github.io`，公开。在 Obsidian 里点发布后，插件会把文章及其英文版复制到这个仓库的 `content/` 下。

为什么这么麻烦？说高级一点叫做「模块化」，说简单点就是分工明确：Obsidian 仓库只负责写，本地是唯一能改文章的地方；私密仓库只负责同步；博客仓库只负责分享和发表。两个 GitHub 仓库都只是从本地推出去的结果，三者通过插件协作。

这也满足了「部分私密」的需求：博客仓库是公开的，但里面只有我点过发布的文章和它们链到的笔记，而且只带标题、网址、摘要、标签、别名和日期这几个属性，库里的其他属性不会带出去。没发布的文章只存在私密仓库里，别人翻博客仓库的源码也看不到。为什么我会有这个需求？不知道为什么，我感觉把自己零碎的思考放到互联网上和裸奔差不多。

下面是架构图：
```text
本地 Obsidian（唯一可以修改文章的地方）
├─ Obsidian Git 自动推送 → 私密仓库
│    ├─ iPhone 上的 Obsidian 拉取 → 给现在的自己看（还没做）
│    └─ 每天定时存进 Google Drive → 留给将来的模型（还没做）
└─ 插件右键发布 → 整理、翻译、改写链接
     → finderlzy.github.io 的 main 分支 → GitHub Actions 自动构建 → 博客网站
                                         └→ 新文章同步到 Blogger
```

## 为什么选 Quartz

由于互联网发展到今天，已经有很多很多的博客框架了，所以我不考虑自己造轮子（最开始确实想自己做一个，但发现现成的已经很多，就打消了这个念头），于是就去找有没有现成的框架可以供我直接使用。可惜的是，并没有一个开箱即用、能满足上面所有需求的框架，所以最后的做法是：**选一个框架负责建站，缺的部分自己补**。

大多数博客框架的功能是差不多的，我选 [Quartz](https://quartz.jzhao.xyz/) 是因为它会显示一篇文章的关系图谱，这个功能我挺喜欢的，所以就没有用 Hexo、WordPress 或者别的框架。

Quartz 是一个静态网站生成器（为了方便，下文就叫它「框架」），负责**把 Markdown 文件变成网站**。用起来很简单：把文章放进 `content/` 文件夹，它就能生成一个静态网站。它的构建过程基本都是由插件完成的，分三类：

- **转换**：把 Markdown 解析、改写成网页内容，比如渲染 LaTeX、代码高亮、处理 Obsidian 的双链。
- **过滤**：决定哪些文章不发布。
- **输出**：生成最终的文件，比如文章页、标签页、搜索索引、RSS。

关系图谱、搜索、反向链接、评论这些功能，也都是一个个插件。所以 Quartz 并不是「先生成页面、再加插件功能」，插件本身就是构建流程。

## 写作和发布：Inbox Filer 插件

我都是在 Obsidian 写文章，所以想写完之后直接发表，但 Quartz 没有提供这个功能，于是就自己写了一个 Obsidian 插件 Inbox Filer，顺便内置了一些我爱用的功能。有一说一，Obsidian 插件真的可以实现挺多功能，这个博客的大部分需求都是靠插件实现的。

这个插件主要做两件事：

- **整理**：用模型补属性、打标签、写摘要、起英文网址，顺便把写成普通文字的数学改成 LaTeX、代码框进代码块，并规范引号。
- **发布**：右键文章，先自动整理一次这篇；再把它放进博客仓库的 `content/blogs/`，它双链到的笔记放进 `content/notes/`，附件放进 `content/attachments/`，双链改写成博客里的路径；然后为每篇翻译一份英文版放进 `content/en/`，最后提交并推送。

英文译文会存回 Obsidian 仓库，可以手动校对；只有中文版改过才会重新翻译，翻译失败时只发中文版。

## 部署

由于我想用 [finderlzy.github.io](https://finderlzy.github.io/) 这个域名，所以博客仓库就叫 [finderlzy.github.io](https://github.com/finderlzy/finderlzy.github.io)，可以直接用 GitHub Pages 部署，网址就是 finderlzy.github.io。我写了`.github/workflows/deploy.yaml`，每次推送到 `main`，GitHub Actions 就自动构建，然后发布到 GitHub Pages。

我还想同步到 Google Blogger，这样方便 Gemini 借助 Google 生态读到我的文章。所以部署成功之后，GitHub Actions 还会再跑一个任务：把这次**新增**的中文正式文章（只算 `blogs/` 下的，笔记和英文版不发），以「摘要 + 原文链接」的形式通过邮件发到 Blogger（Mail2Blogger）。每篇只发一次，改旧文章不会重发；漏发的也可以手动触发补发。

## 对 Quartz 的几处个性化定制

**被带进来的笔记不进首页。** 我不想把零碎的思考放到首页，但又希望博客文章能关联到这些思考。所以 `content/` 下分成 `blogs/` 和 `notes/`：`blogs/` 是正式文章，`notes/` 是被正式文章链到、跟着带进来的笔记。笔记不出现在首页的文章列表里，但仍然能被搜到，也会出现在关系图谱和反向链接里。所以没有用 Quartz 自带的 unlisted，它会把搜索和反向链接里的也一起藏掉。

**英文网址。** 用中文文件名做网址，复制出去会变成一长串 `%E6%A0%87...` 编码，所以每篇文章都用 `permalink` 设一个英文网址，发布到博客仓库时文件名也用它，比如《逸夫楼506悟道》是 `awakening-in-yifu-506`。

**中英文切换。** 英文版放在 `content/en/` 下，网址是 `en/` 加中文版的网址。顶栏加了一个语言切换按钮。语言切换不是插件，进不了配置文件里的工具栏分组，所以在 `quartz.ts` 里把顶栏的工具栏整个重建了。

**评论。** 用 giscus，评论存在博客仓库的 Discussions 里。

**风格。** 日间模式参考的是 [Karpathy 的 GitHub 博客](https://karpathy.github.io/)的风格，素一点；夜间模式是自己调的「冬夜」配色。
